# 核心源码中文教学注释设计

- 日期：2026-08-28
- 状态：待用户审阅
- 范围：`backend/src/deep_research`，随后处理 `frontend/src`
- 非范围：`backend/tests`、`backend/evals`、依赖目录和生成文件

## 1. 目标

为项目核心源码增加适合学习 Agent 工程与准备面试的中文注释。注释帮助读者理解文件职责、依赖作用、关键实现和文件在整体工作流中的位置，同时不改变任何业务逻辑。

## 2. 文件级注释模板

每个源文件顶部使用模块文档字符串或块注释说明：

1. 文件主要职责。
2. 主要第三方库及其用途。
3. 关键类、函数、数据结构或特殊语法。
4. 文件的上游输入、下游输出及其在工作流中的位置。

核心编排文件可加入简短 ASCII 流程图。例如：

```text
API -> Runtime -> LangGraph -> Nodes -> Finalizer
             |-> SQLite checkpoint
             |-> SSE event stream
```

普通模型、工具和 `__init__.py` 文件只标明上下游关系，避免复制完整流程图。

## 3. 代码级注释原则

- 类和公开函数使用中文 docstring 解释职责、参数、返回值和关键约束。
- 对 LangGraph reducer、条件路由、状态 patch、并发调度、SSE 异步生成器、checkpoint、Pydantic 校验、结构化输出修复等特殊机制添加就近解释。
- import 按“标准库、第三方库、项目内部模块”分组，并在分组或重要依赖处解释用途。
- 不解释赋值、普通条件判断等一眼可读的语句。
- 不在注释中复述代码；重点解释“为什么这样设计”和“它在工作流中解决什么问题”。
- 不泄露 `.env` 中的密钥，不把运行时数据写进注释。

## 4. 后端处理顺序

1. `api`：FastAPI 启动、请求模型、路由和 SSE 响应。
2. `services/runtime.py`：运行生命周期、恢复、取消和错误降级。
3. `state` 与 `graph`：Graph State、reducers、节点编排和条件路由。
4. `nodes`：澄清、规划、研究、缺口分析、写作、评审和最终化。
5. `domain`：任务、证据、事件、错误和报告模型。
6. `services`、`tools`、`persistence`、`security`、`prompts`：横切能力和外部边界。
7. 根级配置和 LLM 适配器。

## 5. 前端处理顺序

1. 应用入口和路由。
2. API/SSE 客户端与类型定义。
3. 状态投影、恢复和错误处理。
4. 页面与组件的数据流和交互逻辑。

Vue、TypeScript 文件使用中文块注释和 JSDoc。重点解释响应式状态、生命周期、SSE 事件映射和组件间数据传递，不给模板中的普通标签逐行加注释。

## 6. 质量控制

- 修改只包含注释、docstring 和必要的 import 分组，不改变函数行为和公共接口。
- 分阶段提交修改并检查差异，防止与现有未提交改动冲突。
- 后端运行 Ruff 和项目测试。
- 前端运行测试与生产构建。
- 抽查每类文件，确认均覆盖职责、依赖、关键实现和工作流位置四项要求。

## 7. 完成标准

- 范围内每个源文件都有中文文件级说明。
- 核心函数、类和特殊机制具备有信息量的中文解释。
- 核心工作流文件包含适量流程图或上下游说明。
- 没有明显的逐行翻译式冗余注释。
